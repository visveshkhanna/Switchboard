title: Profiles
description: A profile is a named set of servers and tools that a client is allowed to see.
---

A **profile** is a named selection of tools, such as `personal`, `work` or `acme`. Each client connects to one profile and sees only its tools. You define profiles once, in the web UI or in [`config.json`](/docs/reference/configuration), instead of switching servers on and off in every client.

```json
{
  "name": "work",
  "servers": ["github", "linear", "sentry"],
  "tools": {
    "include": ["notion.search"],
    "exclude": ["github.delete_repository", "sentry.*"]
  },
  "surface": "auto"
}
```

## Which tools a profile has

A profile's tools are worked out in three steps:

1. Every tool of each server listed in `servers`.
2. Plus each tool in `tools.include`, which can add single tools from servers not listed.
3. Minus each tool in `tools.exclude`.

Tools are named `server.tool`, as in `github.create_issue`. `server.*` stands for every tool of a server, so `"exclude": ["sentry.*"]` removes all of Sentry's tools and `"include": ["notion.*"]` adds all of Notion's.

The result is computed in memory and updated as soon as a profile or a server's tool list changes. Connected clients get a `notifications/tools/list_changed` message, so they pick up the change without reconnecting.

## Tool names clients see

Clients see each tool as `server__tool`, as in `github__create_issue`, so two servers can both have a `search` tool. Names are limited to letters, digits, `_` and `-`, and to 64 characters; longer names are shortened with a short hash suffix. The names of the [meta tools](/docs/concepts/tool-surfaces#meta) are reserved.

## Shared servers

Profiles select tools; they do not start their own copies of servers. Switchboard runs **one process per server**, shared by every client and profile that uses it:

- A server starts on the first tool call that needs it, not when the daemon starts.
- Tool lists come from a cached catalog, so `tools/list` answers at once even when no server is running.
- A server that has had no calls for `idleTimeoutSec` (10 minutes by default) is stopped.
- A server that crashes is restarted with backoff. While it is failing, only its own tools are affected.
- Ten clients using the same three servers make three processes, not thirty.

## Presentation

Each profile also chooses its **surface**: how its tools are presented to clients. A small profile can list every tool as is; a large one can be served as three search tools or a single code tool. See [Tool surfaces](/docs/concepts/tool-surfaces).

## Choosing a profile per client

A client chooses a profile by its URL, a header, a client rule or the default profile. See [Profile resolution](/docs/concepts/profile-resolution).
